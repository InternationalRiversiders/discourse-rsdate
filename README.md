# Discourse RSDate

RSDate 的 Discourse 原生插件，页面位于 `/rsdate`。使用论坛登录、认证用户组、管理权限和站内铃铛通知；业务数据存入论坛 PostgreSQL，后台任务使用 Discourse 定时任务。无需另一个 Next.js 服务、Prisma 数据库或 SSO 会话。

## 用户体验

- 个人主页展示资料、必填问卷进度、报名状态和下一次发布时间。
- 资料沿用旧版性别、目标性别、年级、MBTI、星座及长度限制；学校来自认证用户组，校区随学校选择。
- 分模块填写必填或选填问卷，保留题目说明、选项顺序和旧回答；模块更新后标记需要重填。
- 保存资料不会自动报名。完成必填模块后主动报名，可以随时暂停；配对成功自动退出，未配对者保留在池中，再次报名不删除历史。
- 仅本人可查看自己的匹配结果及历史；显示对方资料、论坛主页和模块接近度。
- 管理员可维护问卷、查看参与者、预览、整池发布、手动指定配对、撤回结果和查阅发布/操作记录。
- 自动适配论坛深浅色；校友地图插件提供共同的“校园生活”侧栏分组，单独安装也有导航入口。

## 配置

插件默认关闭，且 `rsdate_read_only` 默认为 `true`。先完成导入与核对，再打开写入。

| 设置 | 用途 |
| --- | --- |
| `rsdate_enabled` | 启用插件 |
| `rsdate_read_only` | 禁止修改、后台匹配、外部向量请求和通知投递 |
| `rsdate_admin_only` | 只允许管理员访问，适合真实数据隔离预览 |
| `rsdate_allowed_groups` | 允许参与的附加论坛用户组 |
| `rsdate_admin_groups` | 运营管理员用户组；论坛管理员也可管理 |
| `rsdate_school_groups` | `学校:认证组:校区一\|校区二;学校二:认证组二:校区`；匹配认证学校的成员也可访问 |
| `rsdate_max_pool` | 单次匹配人数上限，调整前应测试实际池规模 |
| `rsdate_scheduled_enabled` | 默认关闭，启用后每分钟检查是否到期 |
| `rsdate_scheduled_start_at` | ISO8601 格式的最早发布周期；迁移时设为下一次正常周期，避免立即补发停滞的旧周期 |
| `rsdate_publish_weekday/hour/minute/timezone` | 默认上海时间周日 20:00 |
| `rsdate_embedding_key/model` | 可选文本向量服务；密钥为 secret 设置 |

只有配置向量密钥后，后台才会把兴趣、时间安排和介绍发送到 OpenAI embeddings API。已有向量可随历史数据导入，不需要重新生成。测试环境保持密钥为空。

## 匹配与发布

使用一般图最大权匹配（Blossom），优先最大化配对人数，再最大化总分。自动配对遵守双向性别偏好。问卷、兴趣、同校、校区、年级和文本向量分数沿用旧版权重。

手动配对沿用旧版管理员覆盖规则：双方必须已报名、完成当前必填问卷且仍有参与权限，但管理员可以覆盖性别偏好；操作前界面会明确确认。每次发布有唯一周期编号和事务锁，不会重复发布或重复通知。撤回会移除双方本次结果及对应历史，恢复双方报名，其余历史保留。重新配对时清理旧的当前关系，避免单方仍显示旧对象；旧关系的历史仍保留。

通知不发送邮件。导入不生成任何通知。撤销参与资格会阻止后续匹配及待投递通知。

## 从旧版导入

1. 在受保护目录导出，`LEGACY_DATABASE_URL` 指向旧版 PostgreSQL，源应用目录需有生成后的 Prisma 客户端：

   ```sh
   node script/export_legacy.mjs /path/to/old-rsdate /protected/rsdate.json
   ```

   导出使用只读、可重复读事务，不修改原系统，输出文件为 0600。

2. 在安装插件并运行迁移后的**空目标**演练。导出文件包含个人资料、问卷答案、向量和匹配历史，不放进 Git：

   ```sh
   bundle exec rails runner plugins/discourse-rsdate/script/import_legacy.rb /protected/rsdate.json
   ```

3. 核对输出 SHA256、用户 ID、数量和业务状态。关闭目标插件后，将同一 SHA256 通过 `RIVER_IMPORT_SHA256`、`RIVER_IMPORT_APPLY=1` 传入同一命令正式导入。导入遇到未映射用户、非空目标或关联冲突会回滚；相同文件可幂等重试。

导入保留资料与报名状态、文本向量、模块结构、提交日期及是否有效、发布记录、当前匹配和历史匹配。早期整份问卷版本已被旧系统的模块问卷取代，仅保留在 Legacy 档案中，不重复加入当前问卷。

旧域名的主页、资料、等待、结果、问卷模块和管理链接可通过 `/rsdate/legacy` 映射到原生页面。SSO 查询参数不转发。

正式切换需先冻结旧版写入，重新导出最终数据，备份论坛，核对空目标导入和发布周期，再启用原生入口及定时发布。不要同时运行两套发布任务。

## 账号数据

`/rsdate/export` 下载当前账号自己的资料、答案和匹配记录，不包含对方的完整资料或答案。账号删除或匿名化时清理对应业务数据和档案中的答案；账号合并保留目标账号自身资料，清除源账号数据，不擅自合并报名意愿和择偶偏好。

## 验证

`script/regression_test.rb` 仅允许在带 `RIVER_DISPOSABLE=1` 的 `river_community_test` 隔离库运行，会清空该库内 RSDate 表。测试覆盖主动报名、问卷更新、旧版字段限制、分数、发布幂等、历史、撤回、权限、后台任务、时间边界及数据清理。Blossom 的来源与许可证见 `lib/solver/SOURCE.md` 和 `lib/solver/LICENSE`。

生产数据库、账号凭据、向量密钥、导出 JSON、日志和含真实资料的截图应保存在插件仓库之外。
